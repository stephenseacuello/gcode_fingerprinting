% Abstract
\abstract{An attacker who subtly alters a CNC program---shifting a coordinate by a fraction of a millimeter or swapping one motion command for another---can produce parts that look correct but fail under load. Existing sensor-based monitoring cannot catch this: the machine executes whatever it is told, and the sensors report a normal-looking process. We exploit this asymmetry. A decoder trained to reconstruct G-code from sensor signals learns what commands \emph{should} have produced the observed signals; when the claimed program disagrees with that reconstruction, something has been tampered with. (At the 4~Hz effective sampling rate the signals encode program structure and quasi-static process state, not cutting-force spectra.) We find that no single detection strategy works across all attack types. Short-context decoding catches command-level tampering; multi-line decoding catches cross-operation swaps; and a rank-based scoring method---which asks ``is the claimed value in the right \emph{neighborhood},'' not ``is it the most likely value''---recovers coordinate-perturbation detection where conventional likelihood scoring fails (rank vs.\ likelihood gain significant at $p \leq 1.2\times10^{-5}$, DeLong test, Holm-corrected). Sensor-only baselines, by contrast, have no genuine detection signal for these attacks, since the attack leaves the sensors unchanged. The detector runs on six \$33 sensor boards with decoder inference under 6~ms per window (over $11{,}000\times$ real-time on a GPU). We report what works, what does not (multi-head disagreement scoring, temperature-scaled calibration, CUSUM temporal detection), and why---including a per-token confidence analysis that explains the limit on coordinate-attack detection and an adaptive-adversary evaluation in which single-score detection drops to near chance.}
